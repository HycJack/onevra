# Gallery design

The gallery is a standalone example and a native review surface for public components, icons and direct MyGo APIs. It must run without any consumer application.

## Separation from the library

The [entry point](../../source/examples/gallery/main.go) owns startup, appearance selection and shutdown. The [internal gallery](../../source/examples/gallery/internal/gallery/gallery.go) uses `shells/sidebar` and owns demonstration content and state. Examples demonstrate ordinary consumer integration; gallery behavior does not belong in public components.

### Presentation state

Production startup stores application data under `~/.oneo/onevra`. The disk-free `Gallery.New` path keeps examples and native tests isolated from real settings.

- `state.yaml` retains window geometry, sidebar width and expansion, the named navigation route and the last shown application version.
- `config.yaml` retains appearance, language, command-palette preferences and the page-grid preference. Changes apply and save immediately.
- Interactive example values remain in memory, isolated between pages and variants. User content is never persisted.

Unknown routes and unreadable files fall back to defaults; read and save errors are logged. Restored windows are constrained to connected displays where minimum sizes allow. Only YAML filenames are read; older JSON files may be renamed because JSON is valid YAML. An explicit `-theme` launch argument temporarily overrides the saved appearance without rewriting it.

Each new application version opens a standalone welcome entrance as a full-window Shell replacement page. Enter gallery restores saved navigation and sidebar state. The shown version saves immediately; failed saves may show the entrance again. The disk-free path always shows it for review. Gallery's application version stays aligned with `packer.yaml`.

### Navigation and previews

The grouped sidebar contains Welcome, Component status, the Lucide library, desktop integrations, plugins and component pages. Components share purpose-based groups regardless of implementation; a trailing dot marks upstream widgets awaiting an Onevra decision. Plugins and explicitly retained direct-use APIs have no dot. Named routes remain stable when catalog order changes.

Welcome has interactive samples isolated from individual demonstrations. Review pages share a fixed pixel-grid background that Settings can disable, while Welcome and Terminal keep dedicated backgrounds. Examples remain interactive and use independent state per variant. MyGo pages show controls without source listings or tutorial prose. Supporting controls use Onevra equivalents whenever available.

Onevra previews omit disabled variants. Text and Collapsible variants stack; NativeSelect appears below custom Select examples; other variants wrap where appropriate. Markdown renders its document without an extra example heading. The gallery-only Lucide catalog is generated by [lucidegen](../build.md#updating-lucide-icons) and virtualized through GridView; ordinary consumers retain no full-library registry.

### Commands and settings

Command+E on macOS, Ctrl+E elsewhere, and the sidebar search button open the public command plugin. It searches localized page names and English aliases, navigates to pages and opens Settings. Opening clears the query; activation closes the palette. Shortcuts remain window-local and wait behind modal surfaces.

Settings controls whether results appear immediately or after a search. On macOS, optional ABC selection applies while searching and restores the preceding input source on dismissal, preserving a different source manually chosen while open. Search state stays in memory.

The settings toolbar action opens a Onevra Dialog over the current page. macOS Settings… with Command+, targets the main Gallery window even when another window is focused, restores it if hidden or minimized, and leaves the startup entrance when necessary. The public Settings component owns presentation; Gallery owns values, dialog lifetime and persistence. Narrow surfaces use a category selector, and notification-template edits never send notifications.

### Retained examples

| Page | Integration boundary |
| --- | --- |
| Plugins / Code | Retained read-only highlighting, selectable samples and application-owned copying |
| Plugins / Markdown | Cached [fixture](../../source/resources/markdown.md), bundled images and interactive custom code blocks |
| Plugins / Chat | Static conversation, folding, bounded details and composer controls; no model or file access |
| Plugins / Terminal | MyGo shell session, retained across navigation and closed with Gallery |
| Charts / Bar, Line, Area, Stacked bar, Donut | Separate public chart-plugin pages with per-page state, data updates, legends, empty states and selection |
| Layout & containers / Transforms | Editable Onevra controls and anchored popovers under composed transforms, plus a perspective card |
| Layout & containers / Motion | Retargetable spring presets, replayable keyframes and animated poses |

The [chart examples](../../source/examples/gallery/internal/gallery/control_chart.go) use Onevra's public [chart plugin](components.md#charts), with an independent navigation entry for each view and localized application-owned data. The [motion examples](../../source/examples/gallery/internal/gallery/mygo_motion.go) use MyGo's animation methods directly. Neither creates native resources, background loops or timers; animation lifetime follows the built elements and MyGo's reduced-motion preference.

Terminal starts the user's default login shell on first entry. MyGo owns shell selection, the pseudo-terminal, emulation and input. Gallery owns asynchronous native-library loading and the retained session; headless views never start a shell. Packaging and the bundled-library path adapter belong to Gallery, not the library. See [app bundles](../build.md#app-bundles).

### Native resources

| Page | Creation and cleanup |
| --- | --- |
| Desktop / Tray | Explicit enable action creates the icon and notes window; disable or Gallery close destroys both |
| Desktop / System notifications | Explicit send action requests delivery; replacement or shutdown withdraws the demo notification |
| Desktop / Dock menu | macOS-only explicit installation; disable or shutdown restores the previous menu unless another owner replaced it |
| Feedback & overlays / Flyout | Actions open parent-owned native windows; MyGo owns placement, dismissal and parent lifetime |
| Content display / WebView | Gallery retains the native view and hides it under modal layers |

The tray survives page navigation. Its auxiliary window hides on close or blur, retaining the note across hide/show and disable/enable cycles. The main window keeps normal close-to-quit behavior. Notification clicks restore Gallery to their page. Dock actions target their owning Gallery independently of the focused window. Flyout editor and system-popover variants retain their note in application memory.

Native resources are never created merely by rendering an enable button. Platform requirements and manual interaction procedures live in the [development guide](../build.md#native-review), including [tray](../build.md#tray-example), [notifications](../build.md#notification-example) and [Dock menu](../build.md#dock-menu-example).

## Interface language

Gallery offers English, Simplified Chinese and Follow system. The saved preference updates application content, component labels, Shell controls and auxiliary windows immediately. Follow system resolves MyGo's locale at startup; unsupported languages, including Traditional Chinese, fall back to English. Disk-free examples default to English.

Matching embedded YAML catalogs use go-i18n. Stable message IDs remain independent of source copy, route IDs, widget keys and stored values. Static interface text uses IDs; existing demonstration metadata resolves through the English catalog. Language changes preserve drafts, selection, dialog state and navigation. Public component labels use the [localization scope](components.md#localization).

Keep both catalogs equivalent and preserve format placeholders. Translate complete messages, component display names and application-owned menus. API and icon identifiers, filenames and editable fixture content remain unchanged. Installed menus update without losing callbacks or ownership. System menu items, macOS application-menu text and strings internal to MyGo follow their existing language behavior. There is no automatic RTL layout mirroring.

## Component review

The read-only Component status page and startup reminders share [code-owned decisions](../../source/examples/gallery/internal/gallery/mygo_review.go). They distinguish replacements, exclusions, retained upstream examples, newly discovered entries and composition primitives. Empty groups are hidden; replacements group under their Onevra owner. This describes maintenance decisions and example coverage, not every application call site or transitive dependency.

Generation scans exported free functions taking a context first in MyGo's top-level `ui` package, across platform files and including generic constructors. It omits Base constructors and tests. Generated names and locations are checked in, so running Gallery needs neither a toolchain nor a module cache.

The hand-built catalog and reviewed-subpackage map supplement the scanner for methods, `ui/chart`, and plugins. Native menus, every MyGo plugin, transforms and motion remain direct-use APIs. Standard charts use Onevra's chart plugin over upstream primitives; the decision map records that boundary. MyGo's browser target has no Gallery route: Gallery and Packer are desktop applications, and browser packaging is outside their current scope.

After every MyGo upgrade, run `GOWORK=off go generate ./examples/gallery/internal/gallery` from `source/` and review the diff. Ordinary running, building and [Packer](../build.md#app-bundles) use the checked-in snapshot. A generation run cannot establish coverage of new methods or subpackages; review release notes and public signatures too.

Record replacement and exclusion reasons in the decision map, never in generated files. Both hide upstream examples and reminders without affecting Onevra demonstrations. New entries remain visible for review without synthetic examples or build failures. Decisions are neither interactive nor persisted in user settings.

## Verification approach

Ordinary tests use headless views and never open windows. Opt-in native tests run MyGo with temporary user data and capture light, dark and narrow layouts. macOS captures use hidden windows, an accessory process and a test-only AppKit display pump. Foreground lifecycle and input checks need a separate opt-in; other platforms require their own desktop review. See [native review](../build.md#native-review).

`TestNativeCharts` captures selection and data-update transitions on each chart page; `TestNativeMyGoFeatures` captures transform and motion variants. Both include narrow Chinese content inside Shell. Headless interaction coverage includes chart selection, legend visibility, data updates and empty states, transformed editors and popovers, reduced-motion replay and physical-key command shortcuts.

Captures omit OS-composited blur and do not prove pointer, input-method or assistive-technology behavior. Review those interactions, both languages and themes, text scaling, window controls and sidebar resizing in a desktop session. WebView needs its own page capture because window captures leave its native content transparent. Terminal review exercises its real shell and cleanup.
